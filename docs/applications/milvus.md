# Milvus - Vector Database

## Overview

Milvus provides high-performance vector similarity search for AI/ML workloads. It stores and indexes embedding vectors generated by models like `nomic-embed-text` (served by Ollama), enabling semantic search, RAG (retrieval-augmented generation), and recommendation systems.

## Architecture on This Platform

- **Platform**: RKE2 Kubernetes on VMware vSphere / vCenter
- **Namespace**: `ai-platform`
- **Mode**: Standalone (cluster mode disabled)
- **Metadata Store**: Embedded etcd (1 replica)
- **Object Storage**: External MinIO (`minio.minio.svc.cluster.local:9000`, bucket `milvus`)
- **Message Queue**: Pulsar and Kafka disabled (standalone mode uses internal RocksDB WAL)
- **Management UI**: Attu enabled at `https://milvus.homelab.local` via NGINX ingress with TLS
- **Monitoring**: ServiceMonitor enabled for Prometheus scraping

## Best Practices

### Security
- Move MinIO credentials (`accessKey`, `secretKey`) to a Kubernetes Secret referenced via `existingSecretName`
- Attu UI has no built-in authentication; add ingress-level auth or restrict access via network policies
- Use Milvus RBAC (available in recent versions) to control collection-level access
- Encrypt data at rest by enabling MinIO server-side encryption on the `milvus` bucket

### Performance
- Standalone resources (2 CPU / 4Gi) support moderate vector workloads (~1M vectors with 768 dimensions)
- For larger datasets, switch to cluster mode with separate query, data, and index nodes
- Choose index types based on workload: IVF_FLAT for accuracy, HNSW for speed, IVF_PQ for memory efficiency
- Tune `nlist` and `nprobe` parameters to balance search accuracy vs. latency
- etcd is single-replica; monitor its health as metadata corruption affects all operations

### Reliability
- The 10Gi persistent volume stores local indexes and metadata; monitor disk usage
- MinIO provides durable storage for segment data; ensure the `milvus` bucket is included in backup routines
- Back up Milvus collections using the `pymilvus` backup utility before major upgrades
- Monitor etcd health and compact its database periodically to prevent excessive disk usage

## Configuration Reference

| Key | Current Value | Description |
|-----|---------------|-------------|
| `cluster.enabled` | `false` | Standalone mode |
| `standalone.resources.limits` | 2 CPU / 4Gi | Server resource limits |
| `standalone.persistence.size` | `10Gi` | Local data volume |
| `etcd.replicaCount` | `1` | Metadata store replicas |
| `etcd.resources.limits` | 250m CPU / 256Mi | etcd resource limits |
| `externalS3.host` | `minio.minio.svc...:9000` | MinIO endpoint |
| `externalS3.bucketName` | `milvus` | MinIO bucket |
| `minio.enabled` | `false` | Built-in MinIO disabled |
| `attu.ingress.hosts[0]` | `milvus.homelab.local` | Attu UI hostname |
| `pulsar.enabled` | `false` | Pulsar disabled |

## Common Operations and Troubleshooting

```bash
# Check Milvus pods
kubectl -n ai-platform get pods -l app.kubernetes.io/name=milvus

# View Milvus logs
kubectl -n ai-platform logs -l app.kubernetes.io/component=standalone -f

# Check etcd health
kubectl -n ai-platform exec -it milvus-etcd-0 -- etcdctl endpoint health

# Access Attu UI
# Navigate to https://milvus.homelab.local and connect to milvus:19530

# Test Milvus connectivity from a pod
kubectl -n ai-platform run milvus-test --rm -it --image=python:3.11-slim -- \
  pip install pymilvus && python -c "from pymilvus import connections; connections.connect('default', host='milvus', port='19530'); print('Connected')"

# Check collection list via Milvus API
kubectl -n ai-platform exec -it deploy/milvus -- \
  curl -s localhost:9091/api/v1/collections

# Monitor disk usage
kubectl -n ai-platform exec -it deploy/milvus -- df -h /var/lib/milvus
```
